## Buckets and objects

| Feature | Status | Details |
| --- | :---: | --- |
| Buckets | ✅ | Global names, per-account listing, `ExpectedBucketOwner`, AWS's name and Region rules. |
| Objects | ✅ | Metadata, ranges, conditional reads and writes, `CopyObject`, `DeleteObjects`, object attributes and tagging. |
| Checksums | ✅ | CRC32, CRC32C, CRC64NVME, SHA-1 and SHA-256, composite and full-object multipart checksums. |
| Multipart uploads | ✅ | Uploads, part copies, listing and aborts. With SSE-KMS, starting needs `kms:GenerateDataKey` and every part and the completion need `kms:Decrypt`, as in S3. |
| Versioning | ✅ | Versions, delete markers, `ListObjectVersions`, MFA delete settings. |
| Listing | ✅ | `ListObjects`, `ListObjectsV2` and `ListObjectVersions` with delimiters and pagination. |
| Object Lock | ✅ | Retention modes and legal holds. |
| Directory buckets | ✅ | `name--zone--x-s3` buckets with `s3express:` authorization, `CreateSession` credentials (read-only sessions cannot write), `EXPRESS_ONEZONE` storage, `ListDirectoryBuckets` and `RenameObject`. |
| Archived objects | ✅ | Restores answer `202 Accepted` and stay in progress (`ongoing-request="true"`, `RestoreAlreadyInProgress` on a repeat, `InvalidObjectState` on reads) for the settle window (`MWS_ASYNC_DELAY_MS`, default 500 ms of emulated time) instead of AWS's hours, then `s3:ObjectRestore:Completed` fires. |
| Outposts buckets | ❌ | Requests signed as `s3-outposts` are not routed. |

## Security

| Feature | Status | Details |
| --- | :---: | --- |
| Bucket policies | ✅ | Evaluated by the IAM engine with `aws:ResourceAccount` set to the bucket owner; cross-account access needs both sides; anonymous access through public policies or ACLs. The bucket owner's root user can always get, put and delete the bucket policy, even one that denies it. |
| ACLs, ownership controls and Block Public Access | ✅ | Bucket- and account-level Block Public Access (from S3 Control). |
| CORS | ✅ | Configurations and preflight requests. |
| Encryption | ✅ | SSE-S3, SSE-C, and SSE-KMS through KMS with the caller's permissions, plus bucket keys and default encryption. The KMS encryption context is always `aws:s3:arn` (the object ARN, or the bucket ARN with bucket keys) plus any `x-amz-server-side-encryption-context` the caller adds. |
| VPC-only access points | 🟡 | Access points with `NetworkOrigin=VPC` refuse every request with `AccessDenied`: nothing reaches MWS through a VPC. |

## Features that act

| Feature | Status | Details |
| --- | :---: | --- |
| Lifecycle rules | ✅ | Expiration, noncurrent expiration, transitions, multipart aborts and `x-amz-expiration`, on the emulated clock, evaluated before every S3 request. Each action sends its event (`s3:LifecycleExpiration:Delete`, `:DeleteMarkerCreated`, `s3:LifecycleTransition`, by `s3.amazonaws.com`) to notification destinations and EventBridge (`Object Deleted` with reason `Lifecycle Expiration`, `Object Storage Class Changed`). Transitions ignore `TransitionDefaultMinimumObjectSize`. |
| Replication | 🟡 | Asynchronous, as in AWS: a new version reports `PENDING` and has no replica until the settle window (`MWS_ASYNC_DELAY_MS`, default 500 ms of emulated time) has passed; then it is copied (delete markers too, per rule) as the configured role, and the source reports `COMPLETED` or `FAILED` (with `s3:Replication:OperationFailedReplication` and S3's failure reason), the replica `REPLICA`. SSE-KMS objects are re-encrypted under `ReplicaKmsKeyID`, which needs the role's `kms:Decrypt` on the source key and `kms:Encrypt` on the replica key. `PutBucketReplication` checks `s3:PutReplicationConfiguration`, then `iam:PassRole` on the role, then the rules and destinations; versioning cannot be suspended while replication is configured. `ReplicaModifications`, `ExistingObjectReplication` and Replication Time Control are stored but have no effect (no threshold events). |
| Event notifications | ✅ | Destinations are checked when configured (the topic, queue or function policy must allow `s3.amazonaws.com`), topics and queues get an `s3:TestEvent`, and object events are delivered to SNS, SQS, Lambda and EventBridge, including the ones S3 causes itself (lifecycle actions, finished restores, failed replications), with their `lifecycleEventData`, `glacierEventData` and `replicationEventData`. |
| Server access logs | ✅ | Written to the target bucket as `logging.s3.amazonaws.com` in S3's log format (`SimplePrefix` or `PartitionedPrefix`), one object per request rather than AWS's batches. |
| Inventory reports | 🟡 | Delivered daily or weekly at 00:00 UTC on the emulated clock as gzipped CSV or Parquet with manifests, in AWS's layout; ORC is not written. |
| S3 Select | ✅ | `SelectObjectContent` SQL (projections, `WHERE`, `LIMIT`, `CAST`, `LIKE`, `IN`, `BETWEEN`, `CASE`, string and aggregate functions) over CSV and JSON, GZIP or BZIP2 compressed, with scan ranges, streamed as an event stream. |
| S3 Select over Parquet | ❌ | Not supported. |
| Object Lambda | ✅ | Transformed `GetObject`, `HeadObject` and `ListObjects*` run the Lambda function with a presigned `inputS3Url`; its `WriteGetObjectResponse` becomes the caller's response, with AWS's Lambda error codes. |
