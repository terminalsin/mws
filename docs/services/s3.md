# Amazon S3

> Crate: [`mws-s3`](../../crates/services/mws-s3) · Tests: [`tests/e2e-rust/tests/e2e/s3.rs`](../../tests/e2e-rust/tests/e2e/s3.rs)

111 of 112 operations, generated from the AWS model (restXml with S3's quirks:
no error wrapping, `x-id` routing, `x-amz-meta-*`, raw payloads).

## Behaviour

Path-style and virtual-hosted addressing, SigV4 headers, presigned URLs and
`aws-chunked` streaming uploads with chunk and trailer signatures (Signature
Version 2 is refused as for new buckets). Buckets (global names, per-account
listing, `ExpectedBucketOwner`), objects with metadata, ranges, conditional
reads and writes, checksums (CRC32/CRC32C/CRC64NVME/SHA1/SHA256, composite and
full-object multipart), multipart uploads and copies, versioning with delete
markers, `ListObjects`/`V2`/`ListObjectVersions` with delimiters and pagination,
`DeleteObjects`, `CopyObject`, tagging, object attributes, ACLs and ownership
controls, Block Public Access, bucket policies evaluated by the IAM engine
(cross-account needs both sides, anonymous access through public policies or
ACLs), CORS with preflight, SSE-S3, SSE-C and SSE-KMS through KMS with the
caller's permissions, Object Lock (retention, legal hold), and the bucket
configuration APIs (lifecycle, website, logging, notifications, replication,
analytics/metrics/inventory/intelligent tiering, accelerate, request payment).

Lifecycle rules act on the emulated clock (`POST /_mws/clock
{"advanceSeconds":n}` moves it; expiration, noncurrent expiration, transitions,
multipart abort, `x-amz-expiration`), and replication rules copy new versions
and delete markers to the destination as the configured role, with replication
status on both sides. `SelectObjectContent` runs S3 Select SQL (projections,
`WHERE`, `LIMIT`, `CAST`, `LIKE`/`IN`/`BETWEEN`/`CASE`, string functions,
`COUNT`/`SUM`/`AVG`/`MIN`/`MAX`) over CSV and JSON (DOCUMENT/LINES), GZIP or
BZIP2 compressed, with scan ranges, streamed as event-stream
`Records`/`Progress`/`Stats`/`End`.

Directory buckets (`name--zone--x-s3`): `s3express:` authorization for bucket
management, `CreateSession` credentials that the SDKs sign object requests with
(ReadOnly sessions cannot write), `EXPRESS_ONEZONE` storage,
`ListDirectoryBuckets` and `RenameObject`. Object annotations, torrents, and S3
Metadata journal/inventory/annotation table configurations (described, not
queryable). Event notifications are delivered:
`PutBucketNotificationConfiguration` checks event names, filters and overlapping
rules, asks each SNS topic, SQS queue or Lambda function whether S3 may use it
(the topic, queue or function policy must allow `s3.amazonaws.com`), and sends
topics and queues an `s3:TestEvent`; object creations, removals (with delete
markers), tagging, ACL and restore requests then send the S3 event message to
the matching destinations.

Server access logging is delivered: requests to a logging bucket write records
in S3's access log format to the target bucket (`SimplePrefix` or
`PartitionedPrefix` keys, one object per request rather than AWS's batches) as
`logging.s3.amazonaws.com`, which the target bucket's policy must allow; a
target owned by another account is refused with `InvalidTargetBucketForLogging`.
Inventory configurations deliver reports at 00:00 UTC on the emulated clock (the
first midnight after the configuration is put, then daily or weekly) as
`s3.amazonaws.com`, which the destination bucket policy must allow: gzipped CSV
or Parquet data files, `manifest.json`, `manifest.checksum` and a Hive
`symlink.txt` in AWS's layout, with current or all versions, a prefix filter,
the optional fields in AWS's column order, and SSE-S3 or SSE-KMS (the key policy
must let S3 generate data keys); ORC reports are not written.

Other configurations (website, analytics) are stored and returned; archived
objects restore instantly. Access points and Object Lambda access points (from
S3 Control) serve data by ARN (host-style, `{name}-{account}.{endpoint}`) or by
alias (`...-s3alias`, `...--ol-s3`), authorized against the access point policy
and the bucket policy (`s3:DataAccessPointArn` and friends). Object Lambda runs
the Lambda function for transformed `GetObject`, `HeadObject` and `ListObjects*`
requests: the function gets a `getObjectContext` with an `inputS3Url`, presigned
with SigV4 and temporary credentials that act as the caller, that reads the
original object through the supporting access point (with `aws:CalledVia` and
`aws:ViaAWSService`), and its `WriteGetObjectResponse` (status, headers,
metadata, error codes) becomes the caller's response; `LambdaNotFound`,
`LambdaPermissionError`, `LambdaResponseNotReceived`, `LambdaRuntimeError` and
`LambdaTimeout` as in AWS.

## Known gaps

Parquet input for Select. Restores of archived objects complete immediately, and
Outposts buckets (signed as `s3-outposts`) are not routed.
